# Ri tray assets

These SVGs preserve the exact path and viewBox from `ri-mark.svg`. Only the
canvas, scale, placement and fill change. They contain no embedded raster data.

- `ri-trayTemplate.svg` is an 18 by 18 point transparent canvas. The black mark
  is 16 points wide, centered with its original aspect ratio. PNG exports are
  18 by 18 and 36 by 36 pixels. Electron marks the image as a macOS template so
  the menu bar chooses an appropriate foreground in light and dark modes.
- `ri-tray-linux.svg` is a 24 by 24 point warm-white rounded tile with an
  18-point charcoal mark. Its own background keeps the mark visible on light
  and dark Linux panels. PNG exports are 24 by 24 and 48 by 48 pixels.

`desktop/tray-icon.ts` explicitly supplies the 1x and 2x representations to
Electron. The committed PNGs are generated by the existing pinned `sharp`
dependency. They need no image tools at runtime.

Regenerate the four PNGs from the checked-in SVGs at the repository root:

```sh
pnpm exec node --input-type=module <<'JS'
import fs from 'node:fs/promises';
import sharp from 'sharp';
for (const [name, size] of [['ri-trayTemplate', 18], ['ri-tray-linux', 24]]) {
  const svg = await fs.readFile(`public/brand/${name}.svg`);
  for (const scale of [1, 2]) {
    const suffix = scale === 1 ? '' : '@2x';
    await sharp(svg).resize(size * scale, size * scale).png()
      .toFile(`public/brand/${name}${suffix}.png`);
  }
}
JS
```

The focused tray-icon tests verify the master path, rendered dimensions,
transparent monochrome template, Linux contrast colors, and exact SVG-to-PNG
pixel equality. Native panel placement remains a platform qualification check.
