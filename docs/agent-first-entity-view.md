# Agent-first notes and tasks (trial)

Status: reversible UI trial, off by default. Turn it on in Settings > General >
Notes and tasks > Open with: Agent (trial). Written 2026-09-15.

## The bet

The document is not the thing you look at. It is the thing the agent maintains.
What you look at is the agent's brief of it, and what you do is talk. Reading,
adding, changing, and removing all go through a conversation whose edits are
versioned with a diff and undo. The editor stays one click away for the words
themselves.

This is a different claim from "put a chat next to the editor." That already
existed (the focused content chat in the slideout) and it was not reached for,
for reasons that hold for every document co-pilot:

- The editor is in front of you, so micro-edits are faster by hand.
- A blank chat box demands that you formulate intent before you know what is
  in the document.
- The answer lands in a transcript, then you look at the document to see what
  changed. Two places.
- A model turn costs seconds; a click costs nothing.

So the trial does not make the chat bigger. It changes what you see first and
where your hands land:

1. **You see a brief, not a body.** One or two sentences on what this is and
   where it stands, the few points worth knowing, what is still open, and
   suggested next asks specific to this document. For a short document the
   body is shown as-is (it is its own brief) and no model call is made.
2. **The caret lands in the conversation.** Existing documents open with the
   composer focused and teaching copy in it ("Ask, add, change, or remove
   anything in this note. Or just talk."). A new document focuses the title,
   and Enter moves to the composer.
3. **Exact fields stay direct.** Status, deadline, energy, effort, area, and
   the title are one click or one keystroke. Nothing cheap and precise goes
   through a model turn.
4. **Every agent edit is reviewable.** The transcript shows an "Edited note ·
   view changes" chip per edit, the sticky banner shouts when the agent just
   changed the document, and both open the existing diff modal with undo.
5. **Document is one click away.** The header toggle (Agent | Document) shows
   the exact pre-trial surface. Reading the words, hand-editing, and the
   side-panel chat all still work there.

### The brief

Generated by `runHarnessJson` (`src/lib/harness/one-shot.ts`) on the
`standard` tier through the user's subscription harness, like deck generation.
The model receives the title, task metadata (description, outcome, context),
and the body (clipped head + tail past 60k chars), and returns
`{ summary, points, open, suggestions }`, validated with zod.

Freshness is a content hash over title, body, and the task-only content fields
(description, outcome, userContext), with whitespace collapsed first. Live
properties (status, deadline) are excluded on purpose: the UI renders them from
the record, so changing a status does not invalidate a brief. Whitespace is
ignored because the rich editor re-serializes markdown when it mounts (opening
the Document view saved a 7-character blank-line change as a human version
during testing), and that must not read as "the document changed." A cached
brief either matches the document or is reported `stale`; it can never drift.

Validation is shape-only. The first real run failed twice because a bullet ran
past a 300-character cap, which threw away a 49-second call. Lists are now
clamped after parsing (6 points, 5 open, 4 suggestions, empties dropped) and
strings are never truncated mid-sentence.

Cache: one JSON file per entity at `<home>/.work/briefs/<type>/<id>.json`.
`.work/` is the app's regenerable scratch (never synced, safe to delete), which
is exactly what a derived cache is. This keeps the trial free of schema.

Cost model: one model call per distinct content version that is opened in
agent view. Not per keystroke, not per agent edit. A body under 500 characters
never calls the model.

## What to observe during the trial

The task this came from asks for evidence, not vibes. Things worth writing
down after a week of real use:

- Do you open the Document view, and when? If it is "every time, to check," the
  brief is not earning trust. If it is "rarely, to hand-edit a sentence," it is
  working.
- Time to the first useful action on a dense note. Before: scroll and read.
  After: read the brief, click a suggestion or type.
- Whether "add this" through the conversation lands the text where you would
  have put it. This is the most common operation and the prompt is tuned for
  it.
- Whether the suggestions are specific enough to click. Generic ones are a
  prompt problem, fixable without UI work.
- Whether the brief goes stale in a way that misleads. The card says "Changed
  since this brief" and the conversation says what changed, but if that is not
  enough, regenerate after every agent turn (one line in `use-entity-brief.ts`).
- Narrow screens. The agent view is a single column, so it is the same layout
  on a phone as in the slideout. The Document view falls back to the existing
  editor + chat bubble.

## Deliberately not built

- **A paned "all pinned chats" mode.** Listed as an optional comparison in the
  source task. Different problem (many conversations), not tested here.
- **Regenerating the brief after every agent turn.** Churn and cost. Opening
  refreshes; the conversation covers the gap.
- **A briefs table.** The file cache is enough to learn whether briefs matter.
  Promote to a table when a list view wants one-liners or invalidation must
  happen inside the write transaction.
- **A server-side preference.** The localStorage flag is per browser. If the
  trial sticks, add a nullable `user_state` column the way `voiceAutoSend` is
  stored and read it `?? 'editor'`.
- **Replacing the editor.** The Document view is the pre-trial UI, untouched.

## How to turn it off, and how to remove it

Turn off: Settings > General > Notes and tasks > Open with: Editor. Every
surface is back to the previous behavior immediately; nothing about the data
changed.

Remove entirely (if the trial is abandoned):

1. Delete `src/lib/client/entity-view-mode.ts`, `src/lib/briefs/`,
   `src/app/api/entity-brief/`, `src/hooks/use-entity-brief.ts`,
   `src/components/entities/entity-view-toggle.tsx`,
   `entity-brief-card.tsx`, `entity-agent-view.tsx`, and this doc.
2. In the four hosts, drop the `useEntityViewMode` state and the
   `view === 'agent'` branch (the `else` branch is the original tree).
3. In `general-section.tsx`, drop the "Notes and tasks" section.
4. Optionally keep: the `placeholder` prop on the composer, the brief/version
   invalidation in `useDocumentChat`, and the reworded focus prompt. All three
   are improvements independent of the trial.
5. `rm -rf ~/<home>/.work/briefs` on each machine, or leave it; nothing reads
   it.

No migration, no schema, no data to restore.
