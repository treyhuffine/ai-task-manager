# Official MCP migration evidence

Checked September 28, 2026. [migration-evidence.json](migration-evidence.json) contains all 29 current provider IDs and one explicitly noncurrent candidate, PayPal. This is a public-documentation audit. No login, registration, authenticated discovery, or external mutation was performed.

The directory is useful for finding servers, but a listed endpoint does not establish that our app can register an OAuth client or reuse a partner connection. Our public-DCR sign-in path is a good fit for some providers. Other vendors require registered client credentials, administrator setup, a paid plan, or partner onboarding. Tool coverage and client eligibility are separate questions.

| Group | Current providers | Implication |
| --- | --- | --- |
| Already migrated in this worktree | Todoist | Keep the official hosted service and existing compatibility layer. |
| Explicit public DCR documented | Linear, Notion, Jira, Confluence, Calendly, GitLab, Resend | Best next validation candidates. GitLab adds instance/admin conditions, and Jira/Confluence share one service. |
| Generic OAuth documented, DCR details still need verification | Airtable, Readwise, Stripe, Raindrop | Confirm metadata and public-client eligibility before calling these plug-and-play. Several also support bearer credentials. |
| Registered credentials or tenant/partner gating | Slack, Asana, Dropbox, Box, HubSpot, Salesforce, Zoom, Microsoft 365, Google, QuickBooks | A URL-only migration is incomplete. Implement the relevant auth/configuration path and verify eligibility. |
| Different surface, local process, or unresolved official server | Plaid, Mailgun, Discord, Telegram, Zendesk, WhatsApp, X | See distinctions below. These are not all equivalent to “no MCP.” |

The strongest corrections to a directory-only reading:

- **Google now has official hosted servers.** They remain in Developer Preview and need a Cloud project plus configured OAuth. The app has five Google toolkits: Gmail, Calendar, Drive, Docs and Sheets. The directory exposes only the first three. Calendar currently includes event writes, Gmail's published tool list omits sending, and Drive's list omits move/delete/permission writes. [Setup](https://developers.google.com/workspace/guides/configure-mcp-servers), [Gmail tools](https://developers.google.com/workspace/gmail/api/reference/mcp), [Calendar tools](https://developers.google.com/workspace/calendar/api/v3/reference/mcp), [Drive tools](https://developers.google.com/workspace/drive/api/reference/mcp).
- **Microsoft's reusable option is Work IQ, which differs from Anthropic's Microsoft 365 host.** Current Microsoft docs describe a unified server with mail/calendar reads and writes, delegated Entra authentication, tenant enablement and Copilot Credits billing. Do not reduce current availability to older Agent365 Frontier restrictions. [Work IQ](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/mcp/overview), [authentication and billing](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/api-overview), [Microsoft endpoint example](https://github.com/microsoft/iq-series/blob/main/Work-IQ/3-Work-IQ-Tooling-with-MCP-and-Copilot-CLI/cookbook/work-iq-lab03.md).
- **Slack, Asana and Zoom explicitly exclude DCR.** Slack also restricts distribution to Marketplace or internal apps. Dropbox allows DCR only for trusted clients, so our app needs its own credentials or approval. [Slack](https://docs.slack.dev/ai/slack-mcp-server/), [Asana](https://developers.asana.com/docs/connecting-mcp-clients-to-asanas-v2-server), [Zoom](https://developers.zoom.us/docs/mcp/servers/connect-to-zoom-mcp-servers/), [Dropbox](https://help.dropbox.com/integrations/connect-dropbox-mcp-server).
- **Atlassian recommends v2, with `?tools=all` for gateways needing complete paginated discovery.** Some tool groups have admin or authentication-method restrictions, and some consume Rovo credits. Plan one shared connection without losing separate Jira/Confluence action contracts. [Atlassian setup](https://developer.atlassian.com/cloud/rovo-mcp/guides/getting-started/), [authentication](https://developer.atlassian.com/cloud/rovo-mcp/guides/authentication-and-authorization/).
- **Resend is now a strong hosted candidate.** Its official server supports OAuth public DCR and bearer API keys, with rotating refresh tokens. Mailgun explicitly offers an official local process only. [Resend server](https://github.com/resend/resend-mcp), [DCR announcement](https://resend.com/changelog/oauth-support), [Mailgun](https://documentation.mailgun.com/docs/mailgun/mcp).
- **Plaid's official MCP is for developer diagnostics.** Its documented tools do not replace the app's linked-bank transaction/account/balance access. [Plaid MCP](https://plaid.com/docs/resources/mcp/).
- **QuickBooks has a documented hosted developer pilot, but it is invitation only.** It requires partner IP/AppID allowlisting and restricted scopes. Its endpoint differs from the Claude directory endpoint. Intuit also publishes a local server. [Hosted pilot](https://github.com/IntuitDeveloper/intuit-3p-ai-pilot/blob/main/README.md), [local server](https://github.com/intuit/quickbooks-online-mcp-server).
- **X has a real hosted account-data MCP, distinct from its documentation server.** Direct app-only bearer use is read-only. The documented full user-context route uses registered OAuth credentials and the local `xurl mcp` bridge. [X MCP](https://docs.x.com/tools/mcp).
- **Discord's verified official MCP serves documentation.** No official Telegram account-data MCP was found. Zendesk's MCP client is GA, while the public server onboarding was not verified. Meta announces WhatsApp Business Messaging MCP on its official homepage, but the detailed article/reference was unavailable to this audit, so endpoint, generic-client eligibility and production-message coverage remain explicitly unknown. [Discord announcement](https://discord.com/blog/building-on-the-social-layer-of-games-whats-new-from-gdc-2026), [Telegram API](https://core.telegram.org/bots/api), [Zendesk client GA](https://support.zendesk.com/hc/en-us/articles/11105393853210-Announcing-the-general-availability-of-the-MCP-client), [Meta announcement link](https://developers.meta.com/).

Use the generic endpoint documented by the vendor when it differs from the directory. Known differences include HubSpot `/` versus `/anthropic`, Dropbox `/mcp` versus `/claude_app_mcp`, QuickBooks developer pilot versus Claude connector, Resend `/mcp` versus `/`, and PayPal `/http` versus `/mcp`. Preserve both pieces of evidence rather than silently declaring them equivalent.

Before retiring each adapter, validate the actual authentication flow and discovered tools, maintain existing action names, map account identity and pagination, and retain every current toolkit scope. A missing one-to-one REST tool does not necessarily mean the workflow is impossible: some official servers use generic API tools or combine multiple actions. Conversely, broad marketing claims do not prove authenticated workflow parity.
